JDmate —— 把「读 JD → 写开场白」压缩到 3 秒

一个求职者为自己做的 Chrome / Edge 扩展，也是一个把 LLM 用在刀刃上的求职 Agent： 脚本负责拿到可靠事实，模型负责理解语义，规则负责永不失败。 它读懂岗位、结合我的简历写开场白，填进输入框但不替我发送。

哪里用了模型，哪里故意不用

这条分工线是刻意画的：模型只出现在"必须理解语义"的地方，其余交给脚本与规则 —— 更快、更省 token、结果可复现，也不会因为模型抽风就把整个功能弄挂。

环节谁来干为什么这么分
抓页面文本 / 反爬混淆还原 脚本 · 不用模型 「拿到用户真正看到的文本」是模型做不到的事 —— 它只能看见我们喂给它的东西。
JD 结构化（职责 / 要求 / 加分项 / 关键词） LLM Agent 节点 「从杂乱文本里读出结构」正是大模型最擅长的事。但它有门禁： 标题、公司、职责 ≥3、要求 ≥3、关键词 ≥6 时规则直接给结果，根本不调模型。
简历结构化（经历 / 技能 / 量化成果 / 年限） 脚本规则 · 不用模型 简历格式相对固定，规则更稳、不花 token、每次结果一致 —— 这是可复现性的前提。
「简历 ∩ JD」匹配点 本地集合运算 求交集是确定性计算，本地做又快又准还不花钱，比让模型「自己找找看」可靠得多。
开场白生成 LLM · 主战场 唯一真正需要语言能力的地方：一次生成 1~5 条风格与长度都不同的候选。
候选打分与排序 本地 7 维加权 · 不用模型 可解释、可复现、免费。每条都能说清「为什么推荐它、还差哪几个关键词」—— 让模型给自己打分是没法解释的。
事实护栏（数字回查简历） 脚本规则 · 不用模型 不能让模型自己校验自己。它编出来的数字，必须由简历原文来判。
模型挂了怎么办 规则结果兜底 超时 12 秒 / JSON 非法 / 没配 Key → 静默回退到规则结果并说明原因。 模型是增强项，不是依赖项：它挂了，产品只是变笨一点，不会不可用。

每一次 LLM 调用都长成一个可复用的 Agent 节点： 规则先跑 → 门禁 skipLlmIf → 调模型 → Zod 校验 JSON → 与规则结果合并 → 失败静默回退。 后来要加「简历结构化」这类新能力，只需要再写一个 AgentDefinition （提示词 + 输出 schema + 门禁 + 兜底），不用碰主流程。

为什么做这个

求职最费时间的不是「不会写」，而是同一个动作要重复几百遍： 一个岗位几十条要求，我真正对得上的常只有三四条；招聘者每天要看成百条 「您好，我对这个岗位很感兴趣」；而能证明我的东西——量化成果、项目细节、技术选型的理由—— 全埋在简历里，根本没时间一条条挑出来对应。

JDmate 把这个动作压到 3 秒：在 Boss 直聘的岗位页用 LLM Agent 节点读懂当前 JD， 结合我自己的简历生成 1~5 条风格与长度都不同的开场白，本地打分后推荐最合适的一条， 填进聊天输入框——但绝不替我发送。

它具体做什么

六个功能，每一个都对着上面那句「没时间一条条挑出来」；括号里标的是这一步到底用不用模型。

🔍
JD 抽取：脚本拿到事实，Agent 读懂结构

脚本（不用模型）负责「拿到用户真正看到的文本」：先把 Boss 的反爬混淆 （乱码类名、隐藏误导文本）还原成真实 innerText，再剔除「相似职位 / 推荐位 / 页脚」这些 长得像正文的噪声，四级回退。然后交给 LLM Agent 节点：把杂乱文本读成 职责 / 要求 / 加分项 / 关键词。

🤖
Agent 节点：把模型当成不可靠依赖来设计

每一次 LLM 调用都是同一个骨架：规则先跑 → 门禁 skipLlmIf → 调模型 → Zod 校验 JSON → 与规则结果合并 → 失败静默回退。 超时 12 秒、JSON 非法、没配 Key，都退回规则结果并说明原因 —— 模型是增强项，不是依赖项。

✍️
LLM 主战场：写开场白，而不是夸岗位

七层提示词（系统约束 / 简历 / JD 原文 / 本地算好的匹配点 / 偏好 / 风格 / 输出契约） 一次生成 1~5 条候选，风格 5 选、长度 4 档。JD 原文整段进提示词，因为它才是事实来源； 匹配点在本地算好再给模型，既省 token 又提高相关性。

📊
打分不用模型：本地 7 维加权

关键词覆盖、长度适配、量化密度、个性化程度、可读性、新鲜度、风格匹配，加权后减去套话扣分。 可解释、可复现、免费：每条都给分数、推荐理由、命中的关键词、 还差哪几个——不是只丢一句「这条更好」。

🛡️
事实护栏：用规则拦住模型编的数字

话术里出现的每一个数字都会回查简历原文，简历里没有的量化成果会被点名标出。 不能让模型自己校验自己 —— 它编出来的数字，必须由简历原文来判。

🚦
填进去，但绝不发送

只把内容放进聊天输入框，回车由我自己按。这条规则写死在代码里，也写进了提示词里 —— 模型在这一步没有「自动发送」这个选项。

另外两件顺手做的：一键收藏岗位，攒够一批后反查「我反复对不上的是哪几项能力」再回头改简历； 以及面板里的 「查看本次发送给 AI 的内容」 —— 提示词全文可查，你能看到模型到底拿到了什么。

几个想清楚了的取舍

这些是做完之后回头看，最影响成品质量的决定。

不无脑用 AI：模型只负责「理解语义」

抽取、分段、打分、护栏全部先用确定性规则算，只有「规则给不出结构化字段」时才调 LLM； 模型超过 12 秒就直接用规则结果渲染并标注原因。 理由：聊天助手可以等，找工作的工具不能；而且规则算出来的东西可解释、可复现、还免费。

不发送，是唯一不可配置的规则

自动打招呼会让我在完全不知情的情况下说出不像我的话，还可能触发平台风控。 所以这个开关我没有做——不是默认关闭，是根本不存在。

数据不出本机

单一 MV3 扩展、零后端。简历、收藏、生成历史只存在本机 IndexedDB， API Key 经 AES-GCM 加密后落盘。没有账号体系，也没有任何上传。

演示页里不做"状态切换器"

右侧栏的每个状态都得由真实操作走到：关掉站点权限、删掉简历、 把 Base URL 改错、切到 DEMO……给外人看的东西，"方便"不能靠外挂开关。
