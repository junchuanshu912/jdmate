为什么做这个

求职最费时间的不是「不会写」，而是同一个动作要重复几百遍： 一个岗位几十条要求，我真正对得上的常只有三四条；招聘者每天要看成百条 「您好，我对这个岗位很感兴趣」；而能证明我的东西——量化成果、项目细节、技术选型的理由—— 全埋在简历里，根本没时间一条条挑出来对应。

JDmate 把这个动作压到 3 秒：在 Boss 直聘的岗位页读懂当前 JD，结合我自己的简历 生成 1~5 条风格与长度都不同的开场白，本地打分后推荐最合适的一条， 填进聊天输入框——但绝不替我发送。

它具体做什么

六个功能，每一个都对着上面那句"没时间一条条挑出来"。

🔍
读懂 JD —— 四级回退，不卡死

结构化选择器 → 语义选择器 → 启发式 → 手动粘贴。Boss 有反爬混淆（乱码类名、隐藏误导文本）， 所以先把 innerText 还原成真实文本，再剔除「相似职位 / 推荐位 / 页脚」这些 长得像正文的噪声。任何一步失效都有下一步接着，最差也能把 JD 粘进来照样用。

✍️
对着简历说话，而不是对着岗位夸

从简历里挑出与这个岗位真正相关的经历、技能与量化成果，一次给 1~5 条候选。 风格可选（专业硬核 / 数据说话 / 简洁直接 / 亲切自然 / 主动进取）， 长度可选（一句话 / 100-150 字 / 200-300 字 / 400 字内）。

📊
本地打分，并且说清为什么

7 个维度加权（关键词覆盖、长度适配、量化密度、个性化程度、可读性、新鲜度、风格匹配） 再减去套话与夸张的扣分项。每条候选都给分数、推荐理由、命中了哪些关键词、 还差哪几个——不是只丢一句"这条更好"。

🛡️
事实护栏：不许替我编数字

话术里出现的每一个数字都会回查简历原文，简历里没有的量化成果会被点名标出。 宁可少说一句漂亮话，也不能让 AI 替我编一个"提升了 30%"。

🚦
填进去，但绝不发送

只把内容放进聊天输入框，回车由我自己按。这条规则写死在代码里， 也写进了送给模型的提示词里——它没有"自动发送"这个选项。

🔁
收藏岗位，反向优化简历

看到好岗位先一键收藏。攒够一批之后，用它们反查 我反复对不上的是哪几项能力，再回头改简历——投递方向比投递数量值钱。

几个想清楚了的取舍

这些是做完之后回头看，最影响成品质量的决定。

规则先行，模型兜底

抽取、分段、打分全部先用确定性规则算，只有"规则给不出结构化字段"时才交给模型； 模型超过 12 秒就直接用规则结果渲染并标注原因。 理由：聊天助手可以等，找工作的工具不能。

不发送，是唯一不可配置的规则

自动打招呼会让我在完全不知情的情况下说出不像我的话，还可能触发平台风控。 所以这个开关我没有做——不是默认关闭，是根本不存在。

数据不出本机

单一 MV3 扩展、零后端。简历、收藏、生成历史只存在本机 IndexedDB， API Key 经 AES-GCM 加密后落盘。没有账号体系，也没有任何上传。

演示页里不做"状态切换器"

右侧栏的每个状态都得由真实操作走到：关掉站点权限、删掉简历、 把 Base URL 改错、切到 DEMO……给外人看的东西，"方便"不能靠外挂开关。
