# JDmate · 求职沟通助手

求职时真正费时间的不是「不会写」，而是**同一个动作要重复几百遍**：打开一个岗位，JD 里几十条要求，
我真正对得上的可能只有三四条；而我能证明自己的东西全埋在简历里，没时间一条条挑出来对应。

JDmate 把这个动作压到 3 秒。它是一个 Chrome / Edge 扩展：在 Boss 直聘的岗位页读懂当前 JD，
结合**我自己的简历**生成风格与长度都不同的开场白，本地打分后推荐最合适的一条，
并**填进聊天输入框——但绝不替我发送**。

单一 Manifest V3 扩展、零后端，简历与收藏只留在本机 IndexedDB。这个仓库是它的**在线作品演示**。

## 它具体做什么

| | 功能 | 说明 |
|---|---|---|
| 🔍 | **读懂 JD** | 四级回退：结构化选择器 → 语义选择器 → 启发式 → 手动粘贴。先还原 Boss 的反爬混淆文本，再剔除「相似职位 / 推荐位 / 页脚」这些长得像正文的噪声；任何一步失效都有下一步接着，不会卡死 |
| ✍️ | **对着简历说话** | 从简历里挑出与这个岗位真正相关的经历、技能与量化成果，生成 1~5 条候选；风格 5 选（专业硬核 / 数据说话 / 简洁直接 / 亲切自然 / 主动进取），长度 4 档 |
| 📊 | **本地打分并解释** | 7 个维度加权（关键词覆盖 / 长度适配 / 量化密度 / 个性化 / 可读性 / 新鲜度 / 风格匹配）再减扣分项；每条都给分数、推荐理由、命中的关键词、**还差哪几个** |
| 🛡️ | **事实护栏** | 话术里出现的每一个数字都回查简历原文，简历里没有的会被点名标出 —— 不允许 AI 替用户编一个"提升了 30%" |
| 🚦 | **填进去，但绝不发送** | 只把内容放进聊天输入框，回车由用户自己按。这条规则写死在代码与提示词里，**没有"自动发送"这个选项** |
| 🔁 | **收藏岗位 · 反向优化简历** | 一键收藏好岗位；攒够一批后反查「我反复对不上的是哪几项能力」，再回头改简历 |

## 几个想清楚了的取舍

- **规则先行，模型兜底**：抽取、分段、打分全部先用确定性规则算，只有"规则给不出结构化字段"时才交给模型；
  模型超过 12 秒就直接用规则结果渲染并标注原因。聊天助手可以等，**找工作的工具不能**。
- **「不发送」是唯一不可配置的规则**：不是默认关闭，是这个开关根本不存在。
- **数据不出本机**：单一 MV3 扩展、零后端、无账号体系；API Key 经 AES-GCM 加密后落盘。
- **演示页不做"状态切换器"**：见下。

## 说明

- 页面里的**简历与岗位均为虚构的演示数据**，不涉及任何真实个人信息。
- 这是**可交互原型**：没有真实的 AI 调用与网络请求，点任何按钮都不会产生费用。
- 四个页面都是自包含的单文件：无外链资源、无 CDN、无外链脚本，断网也能打开。
- **原型里没有「状态切换器」**：右侧栏的每个状态都必须由真实操作走到
  （点生成 / 重新识别 / 关站点权限 / 删简历 / 切模式 / 设置 + 返回…），
  页面底部有 12 项"点它会真的走一遍"的清单。配好 Key、导入完简历之后才该变的样子，
  用设置页里的**「保存并查看侧边栏 →」**按钮去看——那也是真的保存动作。
- 两个值得留意的细节：原型里那条「✗ Golang」的**未命中关键词**，和事实护栏点出的
  「12 条业务线」**未验证数字**，都是真的算出来的，不是写死的文案。
